# Tallinn Cam Route — Architecture and File Guide

## 1. The big picture

The application uses Next.js, React, TypeScript, and Mapbox. Its source is separated into five main areas:

| Folder            | Purpose                                                                 |
| ----------------- | ----------------------------------------------------------------------- |
| `src/app/`        | Defines pages and the shared application layout.                        |
| `src/components/` | Defines what users see and interact with.                               |
| `src/hooks/`      | Handles React lifecycle, asynchronous requests, and Mapbox integration. |
| `src/lib/`        | Contains configuration and reusable utility functions.                  |
| `src/types/`      | Describes shared data structures used throughout the application.       |

The main idea is: **components display things, hooks manage ongoing behavior, utilities perform specific tasks, and types describe the data.**

There is currently no database or custom API backend. Address searches and driving directions use Mapbox directly from the browser.

The two pages are:

- `/`: the landing page, with a traffic photograph and static map preview.
- `/plan`: the interactive driving-route planner.

The landing-page components render as Server Components. The planner becomes interactive through the `"use client"` boundary in `RoutePlanner.tsx`. Client Components can still have initial HTML generated by Next.js; browser-specific Mapbox initialization happens after mounting, inside an effect.

## 2. Pages: `src/app/`

### `src/app/layout.tsx`

The shared wrapper around every page.

It:

- Defines the HTML document and language.
- Loads the Geist Sans and Geist Mono fonts.
- Imports global CSS.
- Sets the default page title and description.
- Renders the current page through `children`.

### `src/app/page.tsx`

The entry point for `/`, the landing page.

It assembles:

- `Hero`: the large traffic-photo introduction.
- `MapSection`: the static map preview and explanatory content.

It also gets the validated Mapbox token and uses it to construct the static map image URL.

**This page does not initialize an interactive Mapbox map. Its map is an image.**

### `src/app/plan/page.tsx`

The entry point for `/plan`.

It sets the planner's page title and renders `PlannerPage`.

### `src/app/globals.css`

Styles shared across the application:

- Browser resets.
- Default font and document layout.
- Shared CSS color variables.
- Light and dark theme values, following the user's system preference.
- Keyboard focus styling.
- Mapbox and Directions package styles.

### `src/app/favicon.ico`

The icon shown in the browser tab.

## 3. Components: `src/components/`

Each current component has two files:

- `<ComponentName>.tsx`: its UI, event handlers, and local types.
- `<ComponentName>.css`: its appearance and responsive styling.

For example, `MapView.tsx` defines the map container and messages; `MapView.css` defines their size, position, and colors.

Simple component-specific types stay in the `.tsx` file. Substantial or reused component-specific types may warrant a separate type file, while shared domain types belong in `src/types/`.

There are no per-component `index.ts` barrel files. Consumers import named components directly from implementation paths such as `@/components/MapView/MapView`.

### Landing-page components

#### `src/components/Hero/Hero.tsx`

Displays:

- The traffic background image from `public/hero-traffic.jpg`.
- Navigation and branding.
- The main heading.
- Links to the planner and lower page sections.

Its accompanying `Hero.css` controls the background overlay, typography, buttons, and responsive layout.

#### `src/components/MapSection/MapSection.tsx`

Displays:

- The static Tallinn map image.
- A planner-preview card linking to `/plan`.
- “How it works” cards.
- The final call to action and footer.

The address-looking fields here are **not real inputs**. They are part of a link to the planner.

`MapSection.css` styles the preview, cards, and lower landing-page sections.

### Planner components

#### `src/components/PlannerPage/PlannerPage.tsx`

The planner's outer shell:

- Displays the header and home link.
- Places `RoutePlanner` underneath it.

`PlannerPage.css` defines the full-height page and header styling.

#### `src/components/RoutePlanner/RoutePlanner.tsx`

The **central coordinator** of the interactive planner.

It owns:

- The start-point text and selected address.
- The destination text and selected address.
- The current route state.

It connects three components:

- `RouteForm`: edits endpoints.
- `MapView`: displays the map and calculates directions through its hook.
- `DirectionsList`: displays resulting instructions.

When an endpoint changes, it clears the previous route result. When both endpoints have selected suggestions, it moves into the loading state.

Its `updateRoute` callback uses `useCallback` to keep a stable function reference. This avoids restarting the map lifecycle merely because the planner rerenders.

`RoutePlanner.css` stacks the sidebar and map on smaller screens and places them side by side on wider screens.

#### `src/components/RouteForm/RouteForm.tsx`

Displays:

- The start address input.
- The destination address input.
- The swap button.

It does not calculate routes or own endpoint state. Instead, it receives values and callback functions from `RoutePlanner`.

For example, clicking the swap button calls `onSwap`, and `RoutePlanner` performs the state update.

`RouteForm.css` styles the form layout, swap button, and explanatory text.

#### `src/components/AddressInput/AddressInput.tsx`

A reusable autocomplete input used for both endpoints.

It handles:

- Opening and closing the suggestion dropdown.
- Highlighting a suggestion.
- Arrow-key navigation.
- Enter to select.
- Escape to close.
- Mouse selection.
- Accessibility labels and combobox/listbox attributes.

It uses `useAddressSuggestions` to obtain results rather than making requests itself.

There are two relevant values:

- `value`: the text controlled by `RoutePlanner`.
- `query`: the text most recently typed by the user.

Keeping them separate means selecting or swapping addresses does not automatically trigger another autocomplete search.

Selecting a suggestion updates the input text, notifies the planner of the chosen address, and closes the dropdown.

`AddressInput.css` styles the field, start/destination icon colors, dropdown, and highlighted suggestion.

#### `src/components/MapView/MapView.tsx`

A small presentation component that:

- Provides the HTML container for Mapbox.
- Calls `useMapbox`.
- Displays configuration or map-loading errors.

The Mapbox lifecycle is in the hook, not in this component.

The hook returns `containerRef`, which is attached to the container element so Mapbox knows where to render.

`MapView.css` defines the map's dimensions and positions its messages.

#### `src/components/DirectionsList/DirectionsList.tsx`

Displays different content depending on route status:

| Status    | What appears                                       |
| --------- | -------------------------------------------------- |
| `idle`    | Instructions to choose the endpoints.              |
| `loading` | A spinner and loading message.                     |
| `success` | Duration, distance, and turn-by-turn instructions. |
| `error`   | An error message.                                  |

It also chooses an icon for each maneuver, such as a left turn, roundabout, or arrival.

It combines steps from the route's legs into one instruction list and uses the formatting functions from `routeUtils.ts`.

`DirectionsList.css` styles the route summary, instruction rows, empty state, errors, and loading spinner.

## 4. Hooks: `src/hooks/`

A hook is a reusable function that uses React features such as state, effects, or refs.

- **State** stores values that should cause the UI to update when changed.
- **Effects** synchronize React with external systems, such as timers, network requests, and maps.
- **Refs** retain references such as DOM elements and Mapbox instances without causing rerenders.
- **Cleanup functions** release resources when an effect reruns or its component unmounts.

### `src/hooks/useAddressSuggestions.ts`

Manages the autocomplete request lifecycle:

1. Waits until the query has at least **three characters** after trimming whitespace.
2. Waits **250 milliseconds** after typing stops.
3. Calls `fetchSuggestions`.
4. Stores the returned results with the query that produced them.
5. Only exposes results matching the current input.

The delay is called **debouncing**. It avoids making a request for every keystroke.

When the query changes or the input unmounts, the hook clears the pending timer and aborts the old request using `AbortController`.

Search failures currently produce an empty suggestion list rather than a separate error message.

### `src/hooks/useMapbox.ts`

Manages the map and Directions plugin through two effects.

#### Map setup and cleanup

- Creates the map centered on Tallinn.
- Adds zoom and rotation controls.
- Loads the Directions plugin after the map loads.
- Registers route and error callbacks.
- Watches container resizing using `ResizeObserver`.
- Removes controls, map listeners, the observer, and the map when leaving the page.
- Guards asynchronous callbacks so they do not update state after disposal.

The Directions plugin has no public event-unsubscribe method. Its callbacks check the disposal flag, and its control is removed during cleanup.

The plugin is imported dynamically from its browser distribution because its normal entry point uses Node.js filesystem functionality and the browser distribution relies on browser globals.

#### Endpoint changes

- Clears the old route.
- Waits until both selected addresses and the Directions control are available.
- Passes their coordinates to the plugin as the origin and destination.
- Receives the route result.
- Normalizes its geometry.
- Sends the result back to `RoutePlanner`.
- Adjusts the map bounds to show the route.

The plugin uses driving directions, metric units, and no alternative routes. Its built-in inputs and instruction panel are disabled because the application supplies its own `RouteForm` and `DirectionsList`.

## 5. Utilities and configuration: `src/lib/`

### `src/lib/env.ts`

The single location that reads `NEXT_PUBLIC_MAPBOX_TOKEN`.

It:

- Trims and checks the token's format.
- Accepts public Mapbox tokens.
- Returns `null` for missing or invalid configuration.
- Exports the shared configuration message.

This checks **format**, not whether Mapbox will authorize the token or whether it has expired.

Because it is a `NEXT_PUBLIC_` variable, the configured value is included in the browser bundle. It must be a public token, not a secret one. Validation is not a substitute for keeping secret values out of public environment variables.

Next.js embeds public environment variables at build time. Restart development after changing `.env.local`, and rebuild a production deployment after changing its public token.

### `src/lib/mapConfig.ts`

Contains:

- Tallinn's default center coordinates.
- The bounding box used to restrict address searches.
- The Mapbox street-map style.
- `getStaticMapUrl`, which builds the landing page's map-image URL.

This is where you would change the default city or map style. The geocoding request also specifies Estonia in `geocoding.ts`, so changing countries requires updating that request too.

### `src/lib/geocoding.ts`

Handles the actual address-search HTTP request.

**Geocoding means converting an address into coordinates.**

It:

- Sends the query to Mapbox's forward-geocoding API.
- Limits results to Estonia and the Tallinn bounding box.
- Biases results toward Tallinn's center.
- Requests up to three suggestions.
- Validates returned address data and coordinate ranges.
- Discards invalid features.
- Converts valid results into the application's `Suggestion` format.

The distinction is:

- The hook decides **when to search**.
- This utility knows **how to search and interpret the response**.

### `src/lib/routeUtils.ts`

Contains reusable route functions:

- `normalizeRoute`: converts an encoded route line into GeoJSON when necessary.
- `getRouteCoordinates`: extracts usable, finite coordinate pairs.
- `formatDistance`: turns meters into readable meters or kilometers.
- `formatDuration`: turns seconds into minutes or hours.

The normalization handles a plugin behavior where Directions v4 returns encoded polylines even when configured for GeoJSON.

These functions do not manage React state or render UI.

## 6. Shared types: `src/types/`

Types describe expected data and help TypeScript catch mistakes. They do not perform actions at runtime.

### `src/types/address.types.ts`

Defines:

- `Coordinates`: a `[longitude, latitude]` pair.
- `Suggestion`: an address result with its ID, name, context, full address, and coordinates.
- `RoutePoint`: input text plus its selected suggestion, if any.
- `RoutePoints`: the start and end points.
- `RoutePointKey`: either `"start"` or `"end"`.

**Typed text and a selected address are different.** The planner needs a selected suggestion because it supplies coordinates. Editing an address clears its selected suggestion until the user chooses a result again.

### `src/types/route.types.ts`

Defines:

- `RouteStep`: an individual instruction and its maneuver details.
- `DirectionsRoute`: the route shape received from the plugin.
- `RouteGeometry`: a GeoJSON line.
- `DrivingRoute`: a route whose geometry has been normalized.
- `RouteState`: idle, loading, success, or error.

The route-state type prevents inconsistent combinations: a successful state must contain a route, and an error state must contain an error message.

### `src/types/mapbox-gl-directions.d.ts`

Supplies TypeScript declarations for the Directions plugin, which does not provide the needed types itself.

It tells TypeScript which options, methods, and events the application uses. **It describes the plugin; it does not implement it.**

## 7. How a route is calculated, end to end

1. You open `/plan`.
2. `RoutePlanner` starts with empty endpoints and an idle route.
3. `MapView` calls `useMapbox`, which initializes the map after mounting.
4. You type an address into `AddressInput`.
5. `useAddressSuggestions` waits for three characters and a 250 ms pause.
6. `geocoding.ts` requests matching addresses from Mapbox.
7. You select a suggestion.
8. `RoutePlanner` stores its address text and coordinates.
9. After both endpoints are selected and the control is ready, `useMapbox` sets the plugin's origin and destination.
10. The plugin requests driving directions from Mapbox.
11. The hook sends the normalized result back to `RoutePlanner`.
12. `DirectionsList` displays the instructions, and the map fits itself around the route.

**Data travels down through props; user actions and results travel up through callbacks.**

Props are the values and functions a parent passes to a child component. A callback is a function the child invokes to notify the parent of something that happened.

When the user swaps endpoints, the planner exchanges the complete start and destination points and requests the reversed route. When the user edits or clears an endpoint, the previous route is cleared.

## 8. Styling conventions

Component styles use scoped BEM names:

- `.map-view`: the component's root block.
- `.map-view__container`: an element belonging to that component.
- `.address-input--start`: a variant of a component.

These are ordinary CSS classes, not CSS Modules. Their naming convention avoids accidental collisions.

Component-specific styles live beside the component. Global resets, theme variables, and third-party styles live in `src/app/globals.css`.

There are no Tailwind utility classes or inline styling attributes in the application source.

### Main dependencies

- **Next.js:** routing, rendering, builds, fonts, and image support.
- **React:** UI components, state, and lifecycle.
- **Mapbox GL JS:** the interactive map and navigation controls.
- **Mapbox Directions plugin:** driving-route requests and route rendering.
- **Mapbox polyline:** decoding encoded route geometry.
- **Lucide React:** UI icons.
- **Turf:** installed for geographic calculations, but not currently used by the application source.
- **TypeScript, ESLint, and Prettier:** type safety, code checks, and consistent formatting.

### Development commands

- `npm ci`: install dependencies from the lockfile.
- `npm run dev`: start the development server.
- `npm run build`: generate the production build.
- `npm start`: serve the production build.
- `npm run format`: format source TypeScript, TSX, and CSS.
- `npm run format:check`: check formatting without changing files.
- `npm run lint`: run ESLint.
- `npx tsc --noEmit`: check TypeScript without emitting JavaScript.

On a fresh checkout, the production build generates the Next.js route types needed by the standalone TypeScript check. There is currently no committed automated test suite or `npm test` script.

## 10. Where to make common changes

| Change                               | File                                                                         |
| ------------------------------------ | ---------------------------------------------------------------------------- |
| Landing-page text or layout          | `src/components/Hero/Hero.tsx` or `src/components/MapSection/MapSection.tsx` |
| A component's colors or spacing      | Its neighboring `.css` file                                                  |
| Shared theme colors                  | `src/app/globals.css`                                                        |
| Endpoint selection or swapping       | `src/components/RoutePlanner/RoutePlanner.tsx`                               |
| Dropdown behavior                    | `src/components/AddressInput/AddressInput.tsx`                               |
| Search delay or minimum query length | `src/hooks/useAddressSuggestions.ts`                                         |
| Search region or map center          | `src/lib/mapConfig.ts`; country restriction is in `src/lib/geocoding.ts`     |
| Map setup or route fitting           | `src/hooks/useMapbox.ts`                                                     |
| Instruction presentation             | `src/components/DirectionsList/DirectionsList.tsx`                           |
| Distance and time formatting         | `src/lib/routeUtils.ts`                                                      |
| Environment validation               | `src/lib/env.ts`                                                             |
| Shared address or route data shapes  | `src/types/address.types.ts` or `src/types/route.types.ts`                   |

## 11. Current limitations

- Driving routes and directions are implemented, but camera lookup is not. The landing page's camera-related text describes the intended feature.
- Address autocomplete failures currently appear as an empty suggestion list.
- Mapbox functionality requires a network connection and an authorized public token.
- Token validation checks its format, not its permissions or expiry.
- Selected endpoints and route results are held in component state; they are not saved to a database or persisted across a page refresh.
